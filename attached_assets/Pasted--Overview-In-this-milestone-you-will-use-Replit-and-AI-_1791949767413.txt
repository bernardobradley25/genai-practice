## Overview

In this milestone, you will use **Replit and AI-assisted development** to build the smallest working version of the product you described in **Project Problem Framing**.

Your goal is not to build a polished or complete product. Your goal is to create **one basic end-to-end user flow**:

1. The user provides an input or takes an action.
2. The product does something in response.
3. The user receives a visible result.

For example, a meal-planning product might let a user enter ingredients, press a button, and receive several meal suggestions. It does not yet need accounts, saved recipes, shopping lists, payments, or professional visual design.

<aside>
🎭

**This is a prototype, not a finished technical system.** You may use a **Wizard-of-Oz prototype**: the user experiences what the product is intended to do, while some or all of the underlying behavior is simulated, hard-coded, prewritten, or completed manually. The purpose is to test the idea and user experience before investing time in full implementation.

</aside>

A small, believable flow is more valuable at this stage than a large prototype with many incomplete features.

## What You Are Building

Build one simple working slice based on your **Project Problem Framing** submission.

The slice must include:

- A clear starting point
- One central user input, choice, or action
- A visible result
- Enough labels or instructions for another person to understand what to do

The slice may be contained on a single screen. Visual polish is not required.

The underlying technology does **not** need to be fully functional. Acceptable Wizard-of-Oz techniques include:

- Displaying a prewritten or hard-coded result after the user submits an input
- Using sample data instead of a database
- Moving through prepared screens that demonstrate the intended interaction
- Manually creating a response that a future AI system would generate
- Simulating a login, recommendation, analysis, or other complex service
- Demonstrating only a few carefully selected inputs

The prototype should make the intended experience understandable. It does not need a functioning backend, database, authentication system, external API, or live AI model.

Do not spend time adding:

- User accounts
- Payment processing
- Multiple dashboards
- Large amounts of content
- Advanced personalization
- Every feature from your long-term vision
- A custom domain or separate paid hosting

## AI Expectations

Your final course project must include a meaningful role for AI inside the product. Using Replit to write code does not count as the product’s AI functionality.

For this milestone, the product’s AI behavior **may be entirely simulated**. You are not required to connect an AI model or API.

For example, a user might submit information and receive a prewritten recommendation that represents the kind of result the future AI system would produce. This is acceptable if the prototype helps another person understand and respond to the intended experience.

In the README, clearly identify:

- What the future AI system is intended to do
- Which behavior currently works
- Which behavior is simulated or completed manually

Wizard-of-Oz methods are a legitimate prototyping technique, not a shortcut to conceal. Be transparent about them. Never place an API key, password, or access token in a public GitHub repository.

## Required Deliverables

## 1. First Working Slice

A user should be able to open the prototype and move through one central task.

For this assignment, “working” means that the **user-facing flow can be experienced from beginning to end**. It does not mean every underlying system is operational.

The prototype should:

- Accept or represent an input or action
- Show the result the product is intended to provide
- Avoid a dead end in the main flow
- Be understandable without a long explanation

The result may be hard-coded, prewritten, selected from sample responses, or produced manually. The prototype does not need a functioning backend, database, external API, or live AI integration.
