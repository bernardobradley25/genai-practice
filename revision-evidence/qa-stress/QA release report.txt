PERSONA AND WORKAROUND
QA proxy for a busy adult amateur pursuing a comfortable 10K while balancing running, recreational sport, strength and changing work/travel plans. The workaround is calendar notes, manual rescheduling, and deciding whether another sport substitutes for a missed workout. This follows Reflow's project positioning; it is not a recruited ICP usability interview. All scenarios used fictional activity details.

SCORECARD
40 original distinct baseline cases: 20 failed / 20 passed (50% failure).
The first repaired deployment passed all 24 original live scenarios. An additional follow-through scenario (L25) then exposed failure to stage after an AM/PM answer; it was repaired and given positive/negative regression tests.
Final: 49 distinct QA cases passed: 25 deployed live conversation scenarios, 16 local API fault/load cases, eight browser workflows. A final live browser check repeated L25 and applied Saturday at 7 PM correctly; it is not counted as another unique case.
Supporting regressions: 57 logic tests + 15 existing API integration tests = 72 passed, separately from the 16 fault cases. One logic test swept all 1,440 daily start minutes; these iterations are not counted as 1,440 unique scenarios. Typecheck, frontend build and API build passed.

WHAT FAILED AND WHAT CHANGED
- Natural requests: context before an edit, protecting another day, asking for an explanation, shorthand, Spanish requests and a mixed rejection/new edit suppressed valid cards. Intent recognition now considers independent clauses and retains global refusal/uncertainty protection.
- Clock ambiguity: 'move it to 7' was guessed as 7 AM. The API now asks AM/PM first; answering that question continues prior direct edit intent, but not a hypothetical request.
- Boundary reasoning: the AI falsely refused strength at the exact end of soccer. Explicit half-open interval facts and instructions distinguish valid 8:30 PM from overlapping 8:29 PM; shared validation enforces the boundary.
- Invalid current calendars: missing slots, invalid times, overlap, blank titles and contradictory day labels reached the model. The full current week is now checked before any model call.
- Parser failures: malformed/oversized JSON returned framework HTML. Safe JSON 400/413 responses now provide recoverable feedback without exposing stack traces.
- Incomplete upstream results: truncated prose/tools, filtered output, unknown tools and empty replies were treated as success. A valid terminal completion is now required; incomplete output cannot become an applicable review card.
- Long history: the browser could exceed the API's 24,000-character budget. It now retains recent complete messages within both message and character limits, preserving the latest user request. Nine 3,000-character browser diary entries succeeded.
- Scope clarity: instructions now forbid promising next-week editing or inventing a home timezone. Final live responses accurately describe the single sample week and timezone-free clock labels.

STRESS AND RECOVERY
A controlled local burst of 20 simultaneous requests accepted exactly three and returned 429 plus Retry-After for 17. The next request succeeded. Cancelling three occupied slots restored capacity. Heavy load and fault injection used a local scripted upstream to avoid public-service disruption or unnecessary model costs. Live AI calls were bounded and mostly sequential. HTML input remained literal text with no injected DOM image or script dialog.

RELEASE ASSESSMENT
Pass for the defined, limited public fictional-athlete demo: no unresolved failures in the tested matrix, validated calendar writes require a review click, recoverable failures preserve the plan, and the final fixes are published. This is not an assurance that every possible AI response is correct or that the product is ready for unrestricted personal coaching at scale.

Remaining production expansion requirements: durable multi-instance abuse/spending controls (the current 100/hour and three concurrent limits are per process), operating-budget/availability monitoring, and independent target-user evaluation. Personal saved plans, accounts, calendar integrations/export, next-week planning, cycling and overnight sessions remain outside this demo. No medical or training-effectiveness validation was performed. Generated coaching remains probabilistic; semantic tests and prompt fixes reduce observed failures but do not prove universal correctness. A human evaluator has not independently reviewed these outcomes.
